# KidRecord

KidRecord — веб-приложение информационной системы «Моя детская карта». Оно предназначено для ведения медицинской карты ребёнка и напоминаний о профилактических прививках.

Автор концепции и проекта: Ирина Киселева (Irina Kiseleva).

## О проекте

Родители и законные представители накапливают сведения о здоровье и развитии ребёнка в разных местах: бумажные документы, фотографии, заметки, таблицы и отдельные приложения. Из-за этого сложно быстро найти запись, восстановить историю прививок, вспомнить дату следующего профилактического события и увидеть динамику роста и веса. Есть риск, что история и документы окажутся неполными или труднодоступными.

KidRecord объединяет эти сведения в одном приложении. Система хранит медицинскую информацию, помогает не пропускать запланированные события и фиксирует показатели физического развития. Приложение не ставит диагнозы, не назначает лечение и не заменяет консультацию врача. Факт прививки родитель отмечает сам: система не подтверждает вакцинацию автоматически и не определяет индивидуальные медицинские показания.

Интерфейс первой версии собран по макетам Figma «Моя детская карта». Данные на экранах демонстрационные.

## Концепция и возможности

Цель приложения — централизованно хранить медицинскую информацию о ребёнке, напоминать о профилактических прививках и отслеживать показатели развития.

Целевая аудитория — родители и законные представители детей. Информацией о ребёнке могут пользоваться оба родителя или другие законные представители. Доступ даёт владелец профиля и ограничивает его назначенными правами.

Ключевые возможности первой версии:

- профиль ребёнка, включая несколько детских профилей;
- медицинская карта: аллергии, перенесённые заболевания, лекарства и заметки;
- календарь прививок, история выполненных прививок и напоминания;
- учёт роста и веса и просмотр динамики;
- дневник развития, в том числе даты прорезывания зубов и заметки;
- хранение медицинских документов;
- управление доступом второго родителя.

Основной сценарий: регистрация и создание профиля ребёнка, самостоятельное внесение медицинских сведений и истории прививок, напоминание к настроенной дате, ручная отметка прививки после визита в медицинскую организацию. При необходимости родитель добавляет дату, название вакцины и комментарий.

Сейчас реализованы экраны интерфейса, формы из макетов и переходы между разделами. Сохранение выполняется только в памяти браузера и не отправляется на сервер. Регистрация через внешние сервисы, API и медицинская бизнес-логика в эту версию не входят.

## Технологический стек

Фактические зависимости проекта:

- Next.js 16, App Router;
- React 19 и React DOM;
- TypeScript в строгом режиме;
- Material UI 9 и MUI Icons;
- Emotion и `@mui/material-nextjs` для стилей MUI в App Router;
- Zustand — общее состояние записей, которые формы показывают на экранах;
- ESLint и Prettier.

## Структура проекта

```text
src/
  app/            маршруты и страницы Next.js
  components/     переиспользуемые компоненты
  components/ui/  базовые UI-компоненты
  layouts/        общая структура экрана
  store/          Zustand-хранилище записей медицинской карты
  hooks/          пользовательские хуки
  types/          общие типы
  utils/          вспомогательные функции
  constants/      константы, навигация и демонстрационное содержимое экранов
  theme/          тема Material UI
  services/       будущий слой работы с API
  assets/         локальные ресурсы
```

## Установка и запуск

Нужны Node.js 20.9 или новее и npm. Проект проверялся на Node.js 26.

```bash
npm install
npm run dev
```

Приложение открывается по адресу [http://localhost:3000](http://localhost:3000).

Статическая сборка для GitHub Pages:

```bash
npm run build
```

Каталог `out` публикуется адресом [https://irinafkbd.github.io/kidrecord/](https://irinafkbd.github.io/kidrecord/). Публикация выполняется GitHub Actions после попадания изменений в `main`. В настройках репозитория источник Pages должен быть GitHub Actions.

## Команды проекта

| Команда                | Назначение                                |
| ---------------------- | ----------------------------------------- |
| `npm run dev`          | режим разработки                          |

| `npm run format:check` | проверка форматирования                   |
| `npm run type-check`   | проверка TypeScript без генерации файлов  |

## Правила разработки

Приложение построено на App Router. Страницы задают маршрут и метаданные, общая структура экрана и повторяющиеся блоки вынесены в компоненты. Серверные и клиентские компоненты разделяются: интерактивная навигация живёт в клиентских компонентах.

Общие цвета, шрифт и форма элементов задаются темой MUI. Одинаковые карточки, кнопки и навигация не копируются на каждую страницу.

Новые задачи ведутся в ветках `feature/KR-0000`: тип ветки, идентификатор проекта KR и номер задачи с ведущими нулями. В основную ветку напрямую не разрабатывают.

Код пишется на TypeScript со `strict: true`. Перед завершением задачи должны проходить ESLint, Prettier и проверка типов.
